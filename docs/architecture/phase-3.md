# Phase 3: enrolled Windows devices

The Laravel API owns one-use, expiring/revocable enrollment grants; devices have UUIDs and independent RSA public keys. The Windows agent creates a 3072-bit RSA key locally and protects private key material using machine DPAPI in an ACL-restricted directory. Only SYSTEM, administrators and the service identity can read it. No private key is transmitted. Enrollment is interactive or supplied through standard input, never command-line tokens. Matching-key enrollment retries are idempotent until grant expiry; a consumed grant cannot enroll another key.

Agent routes are stateless, separate from browser cookies/CSRF. HTTPS is required; explicitly enabled loopback-only HTTP is permitted for development tests. RSA-SHA256 signatures bind method, exact path, device UUID, timestamp, nonce and raw body SHA256. A five-minute clock window and database nonce uniqueness reject stale/replayed reports. Revocation and reports lock the same device row; disabled credentials cannot update inventory. No command execution, remote-control protocol or consent UI is exposed in this phase.

Current-state tables: devices, device_credentials, enrollment_grants, agent_nonces, device_hardware, device_disks and device_network_interfaces. Heartbeat metrics are overwritten, not stored forever. Inventory replaces its normalized child rows transactionally. Server receipt time determines online/offline state (180-second default). Unknown metrics remain null, never simulated. Offline/never-seen/revoked are distinct; alert evaluation follows in Phase 5. CPU/RAM/storage/network are bounded, read-only local collection.

The .NET worker can run as a visible console process for testing or an explicitly installed Windows service using LocalService. A separate tray application exposes local connection state and links to the support portal; it reads only a non-secret status file, with no privileged IPC. Heartbeats use roughly 60-second intervals with jitter; inventory is sent on change, checked every 15 minutes. Transient failures back off; revoked identity stops reporting. Local status/error output excludes credentials and raw inventory.

The device UI is available only to devices.view. Enrollment and revocation require devices.manage. Administrators can name devices and associate departments. Device details show actual received hardware, disks, network interfaces and last receipt times. Query refresh is 30 seconds; no fake health, remote support or telemetry is shown.

Acceptance: PostgreSQL authorization, one-use grants, expiry/revocation, signature tampering, replay, receipt timestamps, bounded validation and transactional inventory tests; .NET build and protocol checks; real Windows inventory sent to a disposable local server; browser device visibility and responsive layout. Persistent service installation and code signing must be reported separately from a console-mode hardware test.
