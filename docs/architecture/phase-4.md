# Phase 4: approved diagnostics

Seven read-only commands are implemented: network.ping_gateway, network.test_internet, network.test_dns, network.ip_configuration, network.dhcp_information, network.traceroute and system.check_disk. Both server and agent keep independent allowlists. Requests accept no shell text, paths, URLs, hosts, arguments or scripts. Internet/DNS use a fixed Microsoft public endpoint/name; traceroute uses fixed 1.1.1.1 with at most 12 hops. Gateway probes target only detected local gateways. Disk checks report fixed-disk accessibility, capacity and Windows disk status; they do not repair or certify filesystem integrity.

Browser requests require devices.view and devices.diagnostics, an online non-revoked agent >=0.4.0, a reason and a client UUID for idempotency. Optional ticket associations must be visible to the requester. Pending commands are bounded per device. The command record carries requester, source IP, device, ticket, timestamps, status, attempts and result. Audit events track each lifecycle transition without copying diagnostic output into global audit metadata.

Signed agent POST routes claim one command, acknowledge start and submit a bounded result. States: requested → accepted → running → succeeded/failed/rejected; expired and cancelled are explicit terminal states. Queue TTL is five minutes; a lease lasts 90 seconds. Lost claim responses redeliver the same accepted lease. Accepted leases may be retried once before queue expiry; running commands with uncertain completion expire and require an explicit new request. The agent never automatically re-executes a running lease after restart. Result submission is idempotent for an identical result and lease; stale/other-device/changed results are rejected. Revocation rejects outstanding commands. Authorization is checked again when claiming and starting.

The agent polls every 10–12 seconds while connected, maintains its independent heartbeat/inventory schedule, and runs one diagnostic child process at a time. The parent enforces a 30-second deadline and 64 KiB stdout cap, terminating the child on timeout/cancellation. Only a locally allowlisted command ID is passed via ArgumentList, with no shell. Completed results are DPAPI-protected on disk until acknowledgment; network retries submit the saved result rather than repeating the check. Rejected/expired leases discard pending results. Read-only commands are not claimed to have exactly-once side effects.

UI: device diagnostics page, command descriptions/targets, request reason, optional ticket UUID, recent runs and a structured result panel. Queued work can be cancelled; running work cannot be represented as remotely stopped. Failures, timeouts, missing permissions and partial traceroutes remain visible instead of fabricated passes. Users without diagnostics permission cannot view command output.

Validation: allowlist/parameter rejection, idempotency, role and device binding, stale leases, expiry/retry, cancellation, revocation, authorization changes, bounded results and audit; agent command validation and output limits; real Windows request→claim→execute→result browser checks for all seven commands. Persistent service/reboot and production TLS/code signing remain deployment checks.
